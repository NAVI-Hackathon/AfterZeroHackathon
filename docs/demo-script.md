# NAVI · Two-minute demo

**Understand. Guide. Resolve.**  
「NAVI 將使用者的需求，轉化成可執行的服務旅程。」

## 主流程

| 時間 | 操作 | 說明與結果 |
| --- | --- | --- |
| 0:00–0:15 | 首頁，選「我的班機延誤了」 | 使用者不用先知道保險術語、功能名稱或服務入口。 |
| 0:15–0:25 | 「開始分析」 | API 理解需求，同時保留至少約 1.5 秒過場；較慢時持續等待。 |
| 0:25–0:40 | 工作區 35% | NAVI 提供可操作的旅程；服務準備度代表資料完整性。 |
| 0:40–1:00 | 「使用範例登機證」 | 1 秒辨識 → EN JU CHEN / BR197 / 東京 → 台北；35 → 70%。 |
| 1:00–1:25 | 「使用範例延誤證明」 | 14:20 → 21:43 JST = **7 小時 23 分**；70 → 90%，旅程與下一步同步更新。 |
| 1:25–1:45 | 「開始確認」→ 勾選 →「確認資料」 | 100%，資料已準備完成，保障與理賠結果仍由保險公司確認。 |
| 1:45–2:00 | 「前往服務」 | 展示既有理賠服務接續的說明；NAVI 位於使用者與核心系統之間。 |

入口已接 Gemini API，但展示前必須設定 API Key 並跑真實整合測試，才能宣稱本次實際使用 AI。文件辨識、FAQ 與來源仍是 Mock；延誤計算與 workflow / readiness 為確定性邏輯。備援觸發時必須展示畫面的「本次未使用 AI 分析」標示。

## 補充展示

- 右上更多選項 →「重新開始示範」：清除分頁進度並回首頁。
- 助理 →「為什麼需要延誤證明？」→ 資料來源：桌面側面板／手機 bottom sheet。
- 移除延誤證明：準備度返回 70%，確認撤回，下一步重新要求文件。
- 同分頁 reload：保留已完成文件與確認狀態。
- 未知需求「我有個問題」：顯示「我還需要一些資訊」，可補充說明或準備專員摘要。只有已知服務低於 configured threshold 才進 Human Review；信心不可宣稱是已校準機率。
- 車禍／更改繳費方式：展示已辨識需求與「完整服務旅程尚未開放」說明，不展示完整 Workflow。
- 示範導覽勾選「下次文件辨識顯示失敗情境」：下一次辨識失敗不修改資料，重新嘗試可恢復。
- 手機總覽優先看到準備度與下一步；旅程分頁處理文件，助理分頁查詢。
